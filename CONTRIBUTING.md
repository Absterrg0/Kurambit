# Contributing

Thanks for wanting to help make Kurambit better.

## Developer setup

See the [development runbook](docs/operations/development.md#first-checkout) for the first checkout,
development commands and tests.

## Before you start

- Report bugs in [issues](https://github.com/Absterrg0/Kurambit/issues). Include what you did, what
  you expected and what happened, plus the game or log that shows it.
- For features or changes in product behavior, open an issue first so we can agree on direction
  before you write code.
- Small, obvious fixes can go straight to a pull request.

<a id="one-problem"></a>

## One problem per pull request

Keep each pull request to one underlying problem. Unrelated cleanup, renames and refactors belong in
their own pull requests.

## Show that it works

Explain how you verified the change. For game-layer work that means making a real game and playing
it. User-visible changes need before and after screenshots, and motion or timing needs a short
video. Follow the conventions in [AGENTS.md](AGENTS.md); they apply to people and agents alike.
